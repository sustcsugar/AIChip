## 1. 追溯维度与编号规则

| 维度 | 编号 | 来源 | 数量 |
|------|------|------|------|
| 需求 | `REQ-NNN` | spec-001 PRD | 20 |
| 功能规格 | `FS-NNN` | spec-004 §2 | 20 |
| 性能指标 | `M-NNN` | spec-004 §3 | 20 |
| 测试点 | `TP-<功能域>-NNN` / `TP-CHK-NNN` | 本节点派生（自 UC + 约束检查） | 34 |

三类链接（双向追溯）：
- **REQ ↔ SPEC**：需求 → 功能规格/指标承接（数据源 spec-004 的关联 REQ 列）
- **REQ ↔ TP**：需求 → 测试点覆盖（每个 REQ ≥ 1 TP）
- **SPEC ↔ TP**：规格/指标 → 测试点验证（TP 的来源列标注承接的 FS/M）

覆盖率定义：正向 = 已承接 REQ 数 / REQ 总数；反向 = 有来源的 SPEC/TP 数 / SPEC/TP 总数。**双向 100%** 为收敛判据（DoD）。
