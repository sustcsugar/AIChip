# OI 模板（Open Issue / 歧义澄清）

> 用途：全流程需求/规格歧义澄清条目的登记格式标准，台账落点 `docs/spec/spec-003-open-issues.md`。
> 编号规则（ADR-008）：`OI-<节点ID>-<全局序号>`（如 OI-A1-001、OI-A3-006），序号项目全局递增、不随节点重置。
> 术语纪律（ADR-017）：影响范围必须用登记全称编号（REQ/SC/UC/FS/PPAC/FP/BLOCK…），禁用裸简写。

## 模板（台账总表行字段）

```markdown
| OI 编号 | 问题描述 | 提出节点/日期 | 影响范围 | 待答复角色 | 选项/建议 | 状态 | 决策摘要 | 关闭方式/关闭人/日期 | 同步动作 |
```

- **OI 编号**：`OI-<节点ID>-<全局序号>`，全局唯一，不回收不复用
- **问题描述**：一句话点明歧义/矛盾本体（谁与谁冲突、缺什么决策）
- **提出节点/日期**：发现歧义的节点 ID 与登记日期
- **影响范围**：受影响的编号条目（REQ-NNN / FS-NNN / PPAC-NNN / BLOCK-NN / 文档章节），禁裸简写
- **待答复角色**：人类角色（产品/市场/技术负责人/用户/实验环境），决策归属人类
- **选项/建议**：AI 提供的影响分析与备选方案（open 时填写；仅供人类参考）
- **状态**：`open` / `closed`
- **决策摘要**：人工答复后填写，是回写下游文档的唯一依据（closed 条目完整保留，作为历史证据不可删改语义）
- **关闭方式/关闭人/日期**：如"人工答复 / 用户 / 2026-08-20"
- **同步动作**：关闭后需回写的文档（如 `spec-001-PRD.md`、`spec-002-use-cases.md`、`spec-004-system-spec.md`）

## OI 生命周期

```
登记（任一节点发现歧义即追加，全局序号递增）
  → 人工答复（AI 给选项/建议，决策归人类）
  → closed（状态更新，决策摘要落档）
  → 回写受影响文档（按"同步动作"列，如 PRD/UC/spec-004）
  → 变更记录（spec-003 §变更记录追加一行）
```

1. **登记**：任何节点执行中发现需求/规格歧义（指标冲突、范围未定、术语多义），在 spec-003 台账追加一行，状态置 `open`，通知待答复角色。
2. **人工答复**：AI 可预填"选项/建议"列（含影响分析），但不得代猜需求、不得代替决策。
3. **关闭**：人类答复后状态改 `closed`，决策摘要一字不丢语义地记录；决策摘要即下游回写依据。
4. **回写**：按"同步动作"列更新受影响文档，使正文与决策一致；不回写视为未关闭。
5. **变更记录**：每次登记/关闭在 spec-003 变更记录表追加版本行。

## 与 roadmap（RMP）的区别

- **OI**：当前版本**必须关闭**的需求/规格歧义，阻塞相关节点 DoD（如 A1-D1 要求 0 项 open）。
- **RMP**（`AIFlow/state/state-roadmap.md`）：优化方向/增强议题，按 ADR-019 **不进入当前版本**。
- 二者互补：OI 关"这版做不做/做成什么样"，RMP 关"下一版可以更好什么"。已裁定搁置的 OI 可转化为 RMP 登记。
