# Workflow Audit — 整体工作流与流程骨架审查

> 适用者：orchestrator（主 agent）。目的：把"审查整体流程"从概率性的 AI 自由分析，转化为
> **确定性脚本 + 固定不变量 + 分级处置**的可复现流程，消除 AI 审查的随机性与不确定问题。

## 设计原则（规则化）

1. **先机械后语义**：凡能脚本化的检查一律用脚本（确定性、可复现、退出码驱动）；AI 只处理脚本
   覆盖不到的语义项，且必须显式标注【AI 判断·需人工复核】
2. **证据绑定**：每个结论必须有证据（文件路径 / 命令输出 / 退出码），禁止无证据结论
3. **分级处置**：Blocker 必须修复后才能放行；Warning 必须说明理由或修复；Info 仅记录留档
4. **不混层**：机械结论与 AI 判断分开报告，报告格式固定（§5）

## 触发时机

- 架构 / 目录 / 治理层变更后（如目录迁移、skill 重构、模板内化）→ 全量回归审查
- 每个质量门签核前 → 控制流审查
- 阶段切换前（A→B、B→C、C→D、E→F 等）→ 骨架审查
- 用户要求审查整体流程 / 排查治理层不一致时

## 1. 机械层（确定性脚本，全部运行）

| # | 检查 | 命令 | 判定 |
|---|------|------|------|
| M1 | 流程骨架审计（W1-W17） | `python AIFlow/scripts/workflow_audit.py` | 退出码 0=通过；1=有 Warning；2=有 Blocker |
| M2 | 节点依赖与判据 | `python AIFlow/scripts/check_tracker.py` | 输出"检查通过" |
| M3 | Roadmap 结构 | `python AIFlow/scripts/roadmap_check.py` | 输出"检查通过" |
| M4 | 脚手架一致性 | 含于 M1（W10） | 同 M1 |
| M5 | 节点产物校验（如 A1-A3） | `a1_check_req.py` / `a2_check_ppac.py` / `a3_check_interface.py` | 各自 PASS |

**执行顺序 M1→M5；任一退出码 2 立即停止**，先修复 Blocker，不进入语义层。

## 2. 结构不变量（固定清单，逐项核对并附证据）

- N1 节点四层对应：每节点有 详章 + skill + 归属 agent + DoD + gate + tracker 条目（M1 的 W2-W8 覆盖）
- N2 强制关口：D7=关口1（功能收敛）、F5=关口2（时序收敛），gate 必须为 `人工签字`
- N3 收敛环：Loop1（C⇄D 功能环）与 Loop2（E⇄F 时序环）在 SOP §2 定义且可执行
- N4 两层项目模型：`ip/`（IP 项目层）与根目录（SoC 项目层）经 `ip_manifest.json` 关联（path 指向 `ip/`）
- N5 引用完整性：无悬空路径（M1 的 W9/W11 覆盖）
- N6 速查表/职责矩阵/术语表覆盖全部节点与核心缩写（M1 的 W15/W16/W17 覆盖）

## 3. 控制流审查（固定规则，逐项给出证据）

- C1 前置依赖：节点前置必须全部 `passed` 才能进入 `in_progress`（`check_tracker.py` 校验）
- C2 质量门：`gate: 人工签字` 节点必须停下等待人工签字；AI 不得自行置 `passed`
- C3 状态机合法：`pending → in_progress → waiting_review → passed`，判据不满足回退 `iterating`
- C4 签核留痕：D7 / F5 / G2 的签字记录必须存在于 `state-decisions.md` 评审记录表
- C5 归档纪律：`state-*` 文件由 orchestrator 唯一写入（无并发双写）

## 4. 语义层（AI 判断 · 必须人工复核）

> 以下项脚本无法覆盖。AI 输出判断时必须标注【AI 判断·需人工复核】并给出依据，不得作为放行依据。

- S1 流程模型与实际执行是否有偏差（SOP 定义 vs 实际操作）
- S2 节点划分 / 依赖设计的合理性（不变量之外的合理性判断）
- S3 控制流遗漏分支（异常路径、回退路径、可选阶段 H 的切换条件）
- S4 术语与缩写使用规范（对照 `92-术语与缩写表`，是否有未登记缩写）
- S5 语义一致性（文档间口径是否一致，如编号体系规范）

## 6. 处置规则

1. 任何 Blocker → 修复后重跑 M1，不得跳过
2. Warning → 修复或写明理由（留档）
3. 语义层结论 → 必须人工复核后才可作为放行依据
4. 报告归档：写入 `AIFlow/state/`，命名用 `state-` 前缀（如 `state-workflow-audit-<日期>.md`），由 orchestrator 落账
5. 本 skill 自身属于治理资产，若审查发现流程/规范问题，按 review-gate 的"规范回写"纪律同步回写 SOP/详章/skill
