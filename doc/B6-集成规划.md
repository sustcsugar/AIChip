# 节点 B6：集成规划

> 阶段 B | 归属 agent：arch-agent | 对应 skill：`.opencode/skills/node-b6-integration-plan/`

## 1. 节点目的与范围

决定各功能块自研或复用 IP，确定版本基线与复用策略，规划 SoC 集成路径与两级验证策略。作为阶段 B 末节点，评审通过后放行至 C 阶段（C0 IP 接入与合同验证）。

范围：
- 自研 / 复用决策：逐功能块评估（mipi/usb/ddr/axi_uart 走复用，复位 / 时钟 / 中断仲裁 / pinmux 走 SoC 自研 glue）
- 版本基线：`work/soc/ip_manifest.json` 固定每个复用 IP 的版本（git tag）与验证模式
- 复用策略：固定版本只读消费（ip-discipline），改动走 IP 项目新版本发布
- 两级验证策略：`mode: model`（行为模型，早期集成）→ 签核前 `mode: rtl`（真实 RTL 全量回归）的切换判据
- 集成路径与里程碑：IP 接入顺序、关键路径先行、风险与回退机制

不涉及：IP 接口合同的逐项核验（C0）；微架构 / RTL（C 阶段）。

## 3. 执行步骤

### Plan
- 建立功能块清单：全部功能块 + 候选来源（自研 glue / 复用 IP / 外购）
- 确定复用评估标准：功能匹配、接口兼容（AXI / 复位 / 时钟 / 中断）、面积功耗、许可证、维护成本

### Execute
- 自研 / 复用决策：逐功能块评估并记录决策理由（写入 `state/decisions.md`）
- 版本基线：为每个复用 IP 确定版本 tag，初始化 `work/soc/ip_manifest.json`（初始 `mode: model`）
- 复用策略：manifest 锁定的 IP 源码只读消费；任何改动 → IP 项目开新版本发布，再更新 manifest
- 自研 glue 清单：复位、时钟、中断仲裁、pinmux 等 SoC 自有逻辑范围
- 集成路径：定义 IP 接入顺序（关键路径 / 验证阻塞项先行）、集成里程碑与依赖
- 两级验证策略：明确 `mode: model` / `mode: rtl` 语义、切换判据（覆盖率就绪 / 回归基线）、切换裁定人
- 风险与回退：IP 版本不收敛时的回退机制与替代方案

### Measure
- 来源明确率：功能块清单中 100% 有唯一来源标注
- manifest 校验：`python scripts/build_manifest.py --verify` 通过（路径存在、版本 tag 存在、mode 合法）
- 复用占比 / 自研 glue 清单完整性

### Judge
- 对照 DoD（每个功能块来源明确，版本基线确定）逐项检查
- 全部功能块有来源；manifest 可解析且版本可追溯；model→rtl 切换判据书面化
- 不满足 → 修正重测；满足 → 进入质量门（评审），通过后阶段 B 放行

## 6. 收敛判据（DoD）

DoD：每个功能块来源明确，版本基线确定。

可操作判定方法：
- `B6-ip-selection.csv` 中每个功能块有唯一来源（自研 glue / 复用 IP+版本 / 外购），与 B1 模块清单一一对应、无缺漏
- `ip_manifest.json` 通过 `build_manifest.py --verify`：IP 路径存在、版本 tag 可解析、mode ∈ {model, rtl}
- 每个复用 IP 的版本 tag 经 `git -C work/ip/<ip> describe --tags` 可解析并指向既定 commit
- 两级验证策略书面化：model / rtl 语义、切换判据、裁定人已明确
- 自研 glue 范围与复用 IP 范围无重叠、无缺口

## 7. 质量门与签字
