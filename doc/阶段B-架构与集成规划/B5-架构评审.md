# 节点 B5：架构评审

> 阶段 B | 归属 agent：arch-agent | 对应 skill：`.opencode/skills/node-b5-arch-review/`

## 1. 节点目的与范围

组织架构评审，综合 B1–B4 架构产物（如 B6 集成规划已完成可一并纳入），冻结系统架构为 Architecture v1.0。产出评审纪要并完成人工签字，作为阶段 B 的架构冻结里程碑。

范围：
- 评审范围：B1 架构 / B2 地址映射 / B3 互联选型 / B4 模型（含 B6 集成规划若已完成）
- 评审内容：架构完整性、一致性、量化依据、风险与遗留项
- 产出：评审纪要、冻结基线、签字记录

不涉及：节点执行本身的修正（属 iterating 循环）；阶段 B 放行给 C 阶段由 B6 完成后由 orchestrator 执行（B6 是阶段 B 末节点）。

## 2. 输入产物（前置条件）

- [ ] B1 系统架构：`B1-system-arch.md` 等（`state/state-tracker.md` 确认 passed）
- [ ] B2 地址映射：`B2-addr-map.yaml` 与检查报告（passed）
- [ ] B3 互联选型：`B3-bus-interconnect.md` 与量化依据（passed）
- [ ] B4 模型：`B4-pap-report.csv`、`B4-budget-check.md`（passed）
- [ ] B6 集成规划（可选，如已完成则纳入评审；否则架构冻结范围仅含 B1–B4）
- [ ] 输入规格对照：A2 指标、A5 冻结规格 v1.0

前置校验命令：`python scripts/check_tracker.py --node B5`

## 3. 执行步骤

### Plan
- 汇总 B1–B4（及 B6）产物，生成评审材料包
- 按 `.opencode/skills/_shared/templates/review-checklist.md` 建立评审清单，圈定评审范围与遗留项清单

### Execute
- 自检：用 convergence-judge 逐一复核各节点 DoD 证据（无地址冲突、选型量化、预算达标等）
- 组织评审：逐项过清单（架构完整性 / 一致性 / 量化依据 / 风险 / 遗留项）
- 记录评审意见并分类：阻塞项（blocker）与建议项
- 输出评审纪要：结论（通过 / 有条件通过 / 不通过）+ 遗留项（责任人 / 截止 / 影响）

### Measure
- blocker 数 = 0；遗留项均有影响评估、规避措施、责任人与截止日期
- 签字齐备：评审签字记录已写入 `state/state-decisions.md`

### Judge
- 对照 DoD（架构冻结，评审签字）逐项检查
- 全部 blocker 关闭；评审材料无占位符；签字完成
- 有条件通过 → 修复项置 iterating 复审；通过 → 冻结 Architecture v1.0

## 6. 收敛判据（DoD）

DoD：架构冻结，评审签字。

可操作判定方法：
- 评审纪要结论 = 通过（或有条件通过的修复项已完成并通过复审）
- `state/state-decisions.md` 含本节点签字记录（签字人 / 日期 / 结论）
- blocker = 0；遗留项均有责任人 + 截止日期 + 影响评估
- 冻结基线与产物一致：Architecture v1.0 对应 B1–B4（含 B6）既定版本，后续变更须走变更评审流程

## 7. 质量门与签字

- 质量门类型：人工签字
- 未签字不得进入下一节点（B6 集成规划）
- 若 B6 已先行完成并纳入评审，则本签字同时覆盖其评审结论，orchestrator 据此放行阶段 B 至 C 阶段
