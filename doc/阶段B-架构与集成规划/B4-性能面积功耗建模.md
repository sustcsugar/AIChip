# 节点 B4：性能/面积/功耗建模

> 阶段 B | 归属 agent：arch-agent | 对应 skill：`.opencode/skills/node-b4-perf-area-power-model/`

## 1. 节点目的与范围

对性能（Fmax / 吞吐 / 时延）、面积、功耗建立可复算、可更新的估算模型，产出估算报告并与 A2 指标对照，为综合 / 后端预算、架构取舍提供量化基线。

范围：
- 性能模型：逐模块吞吐 / 时延公式化（频率 × 有效效率 × 并发度）
- 面积模型：逻辑规模估算 × 工艺密度 + 宏单元（SRAM / PHY / PLL）+ 复用 IP 已签核面积
- 功耗模型：动态 P = α·C·V²·f + 静态泄漏 + IO / 时钟树开销
- 敏感度分析：频率 / 电压 / 工艺角 ±10% 影响
- 预算对照：SoC 合计 vs A2 面积 / 功耗 / 性能预算，余量 ≥ 15%

不涉及：物理设计阶段精确数据（H 阶段）；STA 签核功耗（F4）。

## 3. 执行步骤

### Plan
- 列出需要建模的模块清单（B1 模块 × 面积 / 功耗 / 性能三类指标）
- 确定参数来源分级：实测（已有 IP 数据）> 参考核 / 外推 > 经验密度；每项标注来源与不确定性

### Execute
- 性能模型：逐模块写公式（如吞吐 = 频率 × 每周期有效字节 × 效率因子），对照 A2
- 面积模型：自研模块按逻辑规模（FF 数 / NAND2 等效门）→ 工艺密度换算 + 宏单元面积 + 复用 IP 面积
- 功耗模型：逐模块动态功耗（α·C·V²·f，翻转率分模块设定）+ 静态功耗（泄漏密度 × 面积）+ 全局开销（时钟树 / IO）
- 敏感度分析：对 V / f / 工艺角做 ±10% sweep，标注敏感项
- 汇总：per-module 表 + SoC 合计 + 预算对照与余量

### Measure
- SoC 合计面积 vs A2 预算；合计功耗 vs A2 预算；各性能指标 vs A2 规格
- 余量计算：估算 vs 预算，目标 ≥ 15%

### Judge
- 对照 DoD（估算满足 A2 指标）逐项检查
- 每个数字有公式 + 参数来源，可复算；不确定性已标注
- 不满足 → 优化架构 / 降频 / 裁剪重复逻辑后重算；满足 → 进入质量门（评审）

## 6. 收敛判据（DoD）

DoD：估算满足 A2 指标。

可操作判定方法：
- 面积合计 ≤ A2 预算，余量 ≥ 15%（含说明）
- 功耗合计 ≤ A2 预算（含最坏角），余量 ≥ 15%
- 性能模型指标（Fmax / 吞吐 / 时延）≥ A2 规格
- 模型确定性：同一参数集重复运行，报告结果一致
- 关键参数均有来源（实测数据 / 参考核 / 经验假设标注），无未注来源的"魔法数字"
