# 节点 B1：系统架构

> 阶段 B | 归属 agent：arch-agent | 对应 skill：`.opencode/skills/node-b1-system-arch/`

## 1. 节点目的与范围

把 A 阶段的规格（功能 / 性能 / 接口）映射为可实现的模块级结构：定义 SoC 顶层框图、子系统 / 子模块划分、数据流。产出系统架构说明书、模块划分清单、数据流矩阵，为后续节点提供骨架。

范围：
- SoC 顶层结构：CPU / 主设备、总线互联（候选）、存储子系统、外设子系统
- 子系统 / 子模块划分：每个功能块的功能描述、来源候选（自研 glue / 复用 IP：mipi/usb/ddr/axi_uart）
- 数据流：主 → 从通路、带宽与时延标注
- 时钟 / 复位 / 电源域框架
- 架构候选方案对比与选型依据

不涉及：地址分配（B2）、总线协议与拓扑选型的量化（B3）、面积 / 功耗 / 性能建模（B4）。B1 只做定性框架，为它们提供接口输入。

## 2. 输入产物（前置条件）

- [ ] A1 需求与场景定义：PRD + 用例清单（由 `state/state-tracker.md` 确认 passed）
- [ ] A2 系统规格书：功能规格、性能指标（Fmax / 吞吐 / 面积 / 功耗预算）— `work/soc/docs/spec-system.md`（passed）
- [ ] A3 接口规格：引脚 / 总线 / 中断 / 存储映射需求 — `work/soc/docs/spec/spec-NNN-interface-spec.md`（passed）

前置校验命令：`python scripts/check_tracker.py --node B1`

## 3. 执行步骤

### Plan
- 读取 A2/A3 规格，提取：性能指标、接口清单、功能场景清单
- 依据功能内聚性 / 复用候选 / 接口边界，形成 2~3 个候选架构方案（例如：单主设备中心式 / 多主全互联式 / 分区桥接式）
- 明确本节点产物清单与落点

### Execute
- 绘制顶层框图（Mermaid）：SoC 顶层、主设备、总线互联、存储子系统、外设子系统、时钟复位电源域
- 模块划分：功能块 → 子系统 / 子模块，逐块标注来源候选（自研 glue / 复用 IP：mipi/usb/ddr/axi_uart）
- 数据流分析：每条主 → 从通路记录路径、带宽需求、时延要求
- 时钟 / 复位 / 电源域划分：确定域边界、异步接口需求、电源域开关候选
- 每个模块输出：功能描述、接口摘要、性能要求、面积 / 功耗占比粗估

### Measure
- 统计：模块总数、子系统数、主 / 从端口数
- 数据流覆盖：A1 场景清单中每个功能场景至少映射到一条数据通路
- 复用占比：复用候选块数 / 总块数

### Judge
- 对照 DoD（架构冻结，模块划分确定）逐项检查
- 检查：模块划分无孤儿功能、无重复功能、数据流图无断裂
- 不满足 → 修正重测；满足 → 进入质量门（评审）

## 6. 收敛判据（DoD）

DoD：架构冻结，模块划分确定。

可操作判定方法：
- 模块划分清单冻结：`B1-module-list.csv` 中每个功能块有唯一归属模块，无重复、无孤儿功能
- 数据流覆盖 100%：A1 场景清单中的每个功能场景在数据流矩阵中至少有一条通路
- 全部 open issue / 风险项有结论（已关闭或已登记风险）
- 一致性：顶层框图与模块清单、端口计数完全对应

## 7. 质量门与签字

- 质量门类型：评审（review-gate）
- 评审检查单：`.opencode/skills/_shared/templates/review-checklist.md`（架构类项：模块划分完整、无占位符、遗留项有责任人）
- 结论：通过 → 签字；有条件通过 → 修复项置 iterating 复审；不通过 → 返回执行
- 未签字不得进入下一节点（B2 地址映射）
