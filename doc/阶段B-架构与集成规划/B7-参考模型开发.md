# 节点 B7：参考模型开发

> 阶段 B 架构 | 归属 agent：arch-agent | 对应 skill：`.opencode/skills/node-B7-reference-model/`

## 1. 节点目的与范围

**目的**：开发**系统级 + 模块级**功能参考模型（golden model），承担双重职责：
1. **前期**：用于算法效果评估与性能评估（在 RTL 就绪前验证算法/架构可行性）。
2. **后期**：作为验证阶段（D 阶段）的 **golden 比对数据**，接入 block/sys 测试环境的 scoreboard，与 RTL 结果自动比对，实现自检闭环、提高仿真效率。

**范围**：
- 系统级模型：`work/soc/model/sys/`（算法/全芯片行为，评估整体效果与性能）。
- 模块级模型：`work/soc/model/block/<mod>/`（每模块一个，对应模块级验证环境 `verif/block/<mod>/`）。
- IP 自带模型随 IP 项目交付于 `work/ip/<ip>/model/`，本节点只消费不重写（对应 manifest `mode: model`）。
- 本节点产出为 golden 模型，**版本冻结**后方可作为比对基准。

## 2. 输入产物（前置条件）

- [ ] A2 系统规格（passed）：功能规格、性能指标
- [ ] A3 接口规格（passed）：接口与协议定义
- [ ] B1 系统架构（passed）：模块划分、数据流
- [ ] B4 性能/面积/功耗估算（passed）：估算作为模型参数输入
- [ ] B6 集成规划（passed）：明确哪些模块复用 IP（其模型随 IP 交付）、哪些自研（需自建模型）

## 3. 执行步骤

### Plan
- 按 B1 模块划分列出建模清单：系统级模型 + 各自研模块模型；复用 IP 用其自带模型。
- 选择建模语言/粒度：算法快速评估用 Python；性能/周期评估用 SystemC 或 C；验证期复用封装为 SV 行为模型或 DPI-C。
- 定义模型规格：输入/输出接口、行为定义、量化/容差策略（与 RTL 比对时允许的误差）。

### Execute
1. 系统级模型：实现算法/全芯片行为，输出可用于效果评估与性能评估的数据。
2. 模块级模型：按 C1/C2 对齐的接口实现每模块行为（端口与 RTL 契约一致，保证验证期可直接对接）。
3. 用规格化测试用例验证模型自身行为与 A2 规格一致（模型自我验证）。
4. 将模型冻结为 golden 版本（版本号 + 变更说明），写入模型规格文档。

### Measure
- 模型用例通过数、算法效果指标（PSNR/吞吐等）、性能指标（周期/带宽/时延）。
- 模型-规格比对结果。

### Judge
- 模型行为与 A2 规格一致（用例全过）。
- 模型版本已冻结为 golden（`state/decisions.md` 记录）。
- 不满足 → 修正模型后重测；满足 → 进入质量门。

## 6. 收敛判据（DoD）

**DoD：模型行为与规格一致，版本冻结为 golden。**

可操作判定方法：
1. 系统级 + 各自研模块模型用例全部通过，行为与 A2 规格一致。
2. 模块级模型端口与 C2/C1 契约对齐（供 D 阶段直接对接 scoreboard）。
3. 算法效果/性能评估结论已产出（对照 A2 指标）。
4. 模型已打 golden 版本号并在 `state/decisions.md` 记录冻结。
5. 复用 IP 模型已在 manifest 中标注 `mode: model` 可被消费。

## 7. 质量门与签字

- 质量门类型：**人工签字**（模型冻结）。
- 未签字冻结前，模型不得作为 D 阶段比对基准。
