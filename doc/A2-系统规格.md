# 节点 A2：系统规格

> 阶段 A | 归属 agent：spec-agent | 对应 skill：`.opencode/skills/node-A2-system-spec/`

## 1. 节点目的与范围

- **目的**：编写系统规格书——功能规格 + 性能指标（Fmax / 吞吐 / 面积 / 功耗预算 / 时延），全部指标可量化、可测试、与 A1 场景对应。
- **范围**：功能模块清单与行为定义、性能指标表、设计约束（工艺/时钟/复位/电源）、可测试性要求、验收标准、需求追溯。
- **不在本节点范围**：具体引脚 / 总线 / 中断 / 地址映射（A3）、架构方案与选型（B 阶段）。本节点定义"指标多高、怎么测"，不定义"接口怎么连"。
- **输出参考**：`templates/spec-system.md`，填写后存入 `work/soc/docs/spec/`。

## 2. 输入产物（前置条件）

- [ ] A1 输出通过（`state/tracker.md` 确认 A1 = passed）：`work/soc/docs/spec/PRD.md`、`work/soc/docs/spec/use-cases.md`
- [ ] 立项输入的工艺 / 目标市场 / 成本档位约束（若有）
- [ ] `templates/spec-system.md`（系统规格书模板，必须遵循其章节结构）
- [ ] 复用 IP 能力清单（背景参考，用于判断哪些指标可由复用 IP 支撑）

## 3. 执行步骤

### Plan
- 读取 PRD / 用例清单，识别功能模块集合与指标需求（性能、面积、功耗、时延）
- 明确指标条目及其**测试方法归属**：功能/吞吐/时延 → 仿真；Fmax/面积 → 综合；功耗 → 功耗分析
- 与 A1 建立对应关系，缺失指标项登记回 A1 或 open issue

### Execute
- **功能规格**：按 `templates/spec-system.md` 第 2 节填写功能模块清单、关键功能行为定义
- **性能指标表**：每项指标给出 目标值 + 单位 + 测试方法 + 来源需求，覆盖 Fmax / 吞吐 / 面积 / 功耗 / 时延
- **约束章节**：工艺、时钟（频率/域）、复位、电源（电压域/档位）、兼容性标准（总线协议版本、外设标准）
- **可测试性要求**：DFT 策略（扫描链接入）、调试接口、自测试（BIST）需求
- **验收标准**：功能验收点（对应 D 阶段验证计划 D1 承接）、收敛验收点（对应 F 阶段时序）
- **需求追溯**：每项功能规格/指标标注来源 REQ/SC 编号（A4 将据此建 RTM）

### Measure
- 指标条目数，逐项核对是否含（目标值 / 单位 / 测试方法 / 来源需求）四要素
- 功能规格条目是否都可追溯到 REQ；每个 REQ 是否至少映射一条规格
- 测试方法与工具链对应性核对

### Judge
- 对照收敛判据：指标可量化、可测试、与场景对应
- 不满足（存在无单位/无测试方法/无来源的指标行）→ 回到 Execute 补齐；满足 → 进入质量门评审

## 4. 工具与命令

- **模板**：`templates/spec-system.md`（章节结构必须遵循）
- **文档工具**：Markdown 表格（指标表）、CSV（指标行主文件，供脚本校验与 A4 引用）
- **指标完整性校验脚本**（建议新增 `scripts/check_metric.py`）：
  ```
  python scripts/check_metric.py --spec work/soc/docs/spec/system-spec.md
  # 输出：缺 目标值/单位/测试方法/来源需求 的指标行；无可追溯来源的规格条目
  ```
- **前置校验**：`python scripts/check_tracker.py --node A2 --deps A1`
- **测试方法对应的工具链**（本节点只定义方法，执行在后续阶段）：
  - 功能 / 吞吐 / 时延 → 仿真：Verilator + cocotb / UVM（开源验证链）
  - Fmax / 面积 → 逻辑综合：DC / GENUS（商用综合链）
  - 功耗 → 功耗分析：Primetime PX（商用功耗链）
  - 时序 Fmax 复核 → STA：Primetime（F 阶段）

## 6. 收敛判据（DoD）

- **指标可量化、可测试，与场景对应**

判定方法：
- 每个性能指标行含 目标值 + 单位 + 测试方法 + 来源需求 四要素（`scripts/check_metric.py` 无空项输出）
- 测试方法可落地：功能/吞吐/时延 → 仿真（cocotb/UVM）；Fmax/面积 → 综合（DC/GENUS）；功耗 → 功耗分析（Primetime PX）
- 每项指标至少关联一个 A1 场景 `SC`；每项功能规格可追溯到 `REQ`
- 与 A1 需求无未追溯项（无 REQ 指向不存在，无规格无来源）
