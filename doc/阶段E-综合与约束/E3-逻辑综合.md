# 节点 E3：逻辑综合

> 阶段 E 综合与约束 | 归属 agent：syn-agent | 对应 skill：`.opencode/skills/node-e3-synthesis/`

## 1. 节点目的与范围

对 RTL 执行逻辑综合，生成门级网表（netlist），并产出综合后 QoR 报告（面积/时序/DRC）。综合结果作为 E4 DRC 检查、E5 LEC 形式验证、E6 门级仿真的输入，也是 F 阶段 STA 的对象。

范围：读入 RTL → elaborate/link → 施加 E1 约束 → 编译优化（compile_ultra 或 syn_generic/syn_map/syn_opt）→ 生成门级网表与报告。综合以时序目标（E1 SDC）为驱动；面积/功耗为次级目标。不包含物理实现与签核 STA。

## 2. 输入产物（前置条件）

- [ ] 前序节点产物（由 `state/state-tracker.md` 确认 passed）：E1 约束开发（评审通过）、E2 库环境设置（检查通过）、C7 RTL 冻结
- [ ] C7 冻结 RTL 文件清单（由 `scripts/build_manifest.py` 解析 `ip_manifest.json` 生成，含 IP 只读消费）
- [ ] E1 `top.sdc`（唯一约束来源）
- [ ] E2 `env_setup.tcl` 与库环境
- [ ] C5 CDC 报告（确认无未决 CDC 违例，避免把 CDC 问题带入综合）

## 3. 执行步骤

### Plan
- 核对 RTL 文件清单与 manifest 版本，确认无越权修改（ip-discipline）
- 确认约束（SDC）与库环境版本已冻结；明确目标频率与 QoR 基线（对比 B4 建模值）
- 明确产物清单：门级网表、QoR 报告、DRC 摘要、SVF（供 E5）

### Execute
- 读入设计：`read_verilog`/`read_hdl`（含 file list），`link` 或 `elaborate` 建立层次
- 设置计算环境：`set_operating_conditions`（按目标角，如 ss/rc_worst）；施加约束 `read_sdc top.sdc`
- 编译：
  - DC：`compile_ultra`（含拓扑优化、边界优化；超深流水建议加 `-timing`），或 `compile` 基准流程
  - GENUS：`syn_generic` → `syn_map` → `syn_opt`（`-effort high` 按需）
- 写 SVF：`write_svf`（DC）导出综合变换记录，供 E5 Formality 匹配（GENUS 对应 `write_db`/等价 setup 记录）
- 报告与网表落盘：`report_area`、`report_qor`、`report_timing`、`report_constraint -all_violators`、`report_clock_gating`（时钟门控质量）；`write -format verilog`/`write_hdl` 网表，`write_sdf`（可选，供门级仿真）

### Measure
- 收集：总面积与门数、时钟域内 WNS/TNS（综合后）、DRC violation 计数、时钟门控率、单元类型统计
- 与 B4 面积/性能建模基线比对，记录偏差

### Judge
- 综合 DRC clean（max_transition/capacitance/fanout 违例数 = 0，或以 E4 全量确认）
- 时序残留违例数量已记录（供 F 阶段处理；E 阶段不追求时序收敛）
- 不满足 → 调整综合选项/约束后重综合（迭代）；满足 → 进入质量门（检查）

## 4. 工具与命令

- 工具：DC（Design Compiler）或 GENUS；后端商用工具，由人机协同脚本驱动
- DC 流程脚本（`work/soc/syn/scripts/synth.tcl`）：
  - 读入：`read_verilog [list ...]`；`current_design <top>`；`link`；`set_operating_conditions <corner>`
  - 约束：`read_sdc top.sdc`（或 `source top.sdc`）
  - 编译：`compile_ultra` / `compile_ultra -timing`
  - SVF：`write_svf -file <svf_path>`
  - 输出：`write -format verilog -hierarchy -output top_netlist.v`；`write_sdf top.sdf`；`write -format ddc -hierarchy -output top.ddc`
- GENUS 流程（等价步骤）：
  - 读入：`read_hdl -vhdl | -sv [list ...]`；`elaborate <top>`
  - 约束：`read_sdc top.sdc`；`set_db operating_condition <corner>`
  - 编译：`syn_generic`；`syn_map`；`syn_opt`
  - 输出：`write_hdl -mapped top_netlist.v`；`write_sdf top.sdf`；`write_db top.genus.db`
- 报告命令：
  - `report_area`、`report_qor`、`report_power`
  - `report_timing -delay_type max|min -path_type full -max_paths <n>`、`report_constraint -all_violators`（DC）/ `report_constraints -all_violators`（GENUS）
  - `report_clock_gating`、`report_hierarchy`、`report_design_rules`
- 门数核算：`report_area` 折合 NAND2 门数（单位门换算按工艺）

## 6. 收敛判据（DoD）

**综合 DRC clean**，判定方法：
- `report_constraint -all_violators`（DRC 部分）与 `report_design_rules` 中 max_transition/max_capacitance/max_fanout/min_pulse_width 违例计数 = 0
- 网表完整落盘（无黑盒、无悬空例化），`link` 后无 unresolved reference
- 面积/时序 QoR 报告生成齐全，可追溯
- 残留时序违例（若存在）已全量记录于报告，不掩盖（进入 F 阶段处理）

## 7. 质量门与签字

- 质量门类型：检查（check）
- 检查重点：DRC 是否 clean、网表完整性、报告齐全性、脚本可复现性
- 未签字不得进入 E4
