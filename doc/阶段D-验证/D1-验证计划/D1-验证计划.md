# 节点 D1：验证计划

> 阶段 D 验证 | 归属 agent：verify-agent | 对应 skill：`.opencode/skills/node-D1-vplan/`

## 1. 节点目的与范围

编写验证计划 vplan：测试点（testpoint）、场景、覆盖率目标。本节点是功能收敛环 Loop 1 的起点，将需求/规格（A4 RTM、A2 系统规格）与微架构（C1/C2）转化为可执行的验证任务清单，为 D2–D7 提供唯一依据。

范围：
- 两级环境全覆盖：模块级 `verif/block/<mod>` 与系统级 `verif/sys/`
- 测试点表（TP）与需求/规格双向追溯（对应 vplan 模板第 2 节）
- 场景清单：功能 / 边界 / 异常 / 互操作（对应模板第 4 节）
- 覆盖率目标量化设定（对应模板第 5 节），作为 D6 收敛基准与 D7 签核标准

## 2. 输入产物（前置条件）

- [ ] A4 需求可追溯矩阵（RTM）passed（`state/tracker.md` 确认）
- [ ] A5 规格冻结 passed
- [ ] B6 集成规划 passed（模块来源、复用策略、IP 版本基线）
- [ ] C1 微架构规格 passed（状态机 / 握手 / 流水线描述）
- [ ] C2 模块接口契约 passed（端口、时序、握手协议）
- [ ] `work/soc/ip_manifest.json` 已 pin IP 版本（mode: model / rtl）
- [ ] 模板 `templates/vplan.md` 存在

## 3. 执行步骤

### Plan
1. 读取 RTM、系统规格、微架构规格、接口契约，确认验证目标与两级验证边界。
2. 复制 `templates/vplan.md` → `work/soc/docs/vplan/vplan.md`。
3. 列出 DUT 清单（block 级各模块 + sys 级 soc_top），确定范围边界与例外。

### Execute
4. 拆解测试点：每条需求/规格条目至少映射一个 TP；复杂功能按分支细拆（ID 格式 `TP<序号>`）。
5. 按模板第 2 节填表：`测试点 / 描述 / 场景 / 来源规格需求 / 测试类型（定向/随机/断言）`。
6. 按模板第 4 节规划场景清单，明确环境层次（block / sys）与复用资产（`verif/common/` 的 VIP、行为模型、memory model）。
7. 按模板第 5 节设定覆盖率目标（代码 + 功能 + 断言），按模板第 6 节写回归策略，按第 7 节写签核标准。

### Measure
8. 统计度量：TP 总数、场景数、覆盖率目标值、两级环境覆盖分配。
9. 运行 `python scripts/check_tracker.py --node D1`。

### Judge
10. 对照收敛判据逐项检查（见第 6 节）。
11. 不满足 → 定位缺口（漏测需求 / 无来源的孤儿 TP）→ 修正后重测；满足 → 进入质量门。

## 4. 工具与命令

- 模板：`templates/vplan.md`（输出必须遵循其 7 节结构）。
- 追溯校验：
  - 正向：解析 RTM 需求 ID，逐一确认在 vplan 测试点表存在映射（可写 `scripts/rtm_trace_check.py` 或手动表格比对）。
  - 反向：解析 vplan `来源规格/需求` 列，确认每个 TP 有合法来源 ID。
- 状态校验：`python scripts/check_tracker.py --node D1`。
- 文档工具：Markdown 表格；建议 vplan 测试点表按 `block/`、`sys/` 分表。

## 6. 收敛判据（DoD）

**测试点与需求双向覆盖。**

可操作判定方法：
- 正向覆盖：每条需求/规格条目 ≥ 1 个 TP（RTM → TP 全覆盖 100%）。
- 反向覆盖：每个 TP 能追溯到唯一来源需求/规格 ID，无孤儿 TP。
- 覆盖率目标已量化写入 vplan 第 5 节（不写目标 = 未达标）。
- 两级环境均有对应 TP（block 级与 sys 级测试点均非空）。
- `python scripts/check_tracker.py --node D1` 通过。

## 7. 质量门与签字

- 质量门类型：评审（使用 `templates/review-checklist.md` 验证类清单）。
- 未签字不得进入 D2。
