# 节点 A5：规格评审冻结

> 阶段 A | 归属 agent：spec-agent | 对应 skill：`.opencode/skills/node-A5-spec-review-freeze/`

## 1. 节点目的与范围

- **目的**：组织规格评审，输出评审纪要，关闭全部 Blocking 问题，将 A1–A4 产物定稿为规格 v1.0 并冻结基线。
- **范围**：评审材料打包、预审、评审会组织与记录、问题分级与关闭、规格 v1.0 冻结、签字留档。
- **不在本节点范围**：规格内容本身的重大返工（若评审出现 Blocking 级内容缺失，返工回 A1–A4 对应节点，本节点不代做）。
- **位置意义**：A5 是阶段 A 的收口节点，冻结后进入阶段 B（架构与集成规划），规格变更须走变更流程。

## 2. 输入产物（前置条件）

- [ ] A1–A4 输出全部通过（`state/state-tracker.md` 确认 A1、A2、A3、A4 = passed）：
  - `spec-001-PRD.md`、`spec-002-use-cases.md`、`spec-NNN-system-spec.md(+csv)`、`spec-NNN-interface-spec.md(+csv)`、`spec-NNN-rtm.md`、`spec-NNN-rtm-report.md`
- [ ] `templates/review-checklist.md` — 评审检查清单（review-gate skill 调用）
- [ ] 评审参与角色：设计（RTL）、验证（D 阶段）、架构（B 阶段）代表，由 orchestrator 协调
- [ ] `state/state-decisions.md` — 评审结论与签字记录落点

## 3. 执行步骤

### Plan
- 汇总 A1–A4 产物为评审材料包，明确评审范围、评审角色与时间安排
- 确定评审问题分级规则：Blocking（必须关闭才能冻结）/ Non-blocking（可遗留，需记录责任人）

### Execute
- **预审**：AI 按 `templates/review-checklist.md` 逐项预审全部规格产物，输出预审问题清单
- **评审会**：人主持，逐条确认预审问题与新增问题；AI 实时记录结论到评审纪要
- **问题分级与关闭**：Blocking 问题分配责任人并关闭（可能需要回退 A1–A4 修正，循环直至关闭）；Non-blocking 列出影响、责任人、目标节点
- **规格定稿**：将 A1–A4 产物定稿为规格 v1.0，打冻结基线
- **签字留档**：评审结论、签字人（角色/日期）写入 `state/state-decisions.md`

### Measure
- 评审问题总数、Blocking / Non-blocking 数量、已关闭数量
- `templates/review-checklist.md` 勾选完成度
- 签字记录完整性（角色 / 日期）

### Judge
- 对照收敛判据：规格冻结、评审签字
- 无未关闭 Blocking 问题 + 签字齐全 + 基线已冻结 → 通过；否则回到 Execute 关闭剩余 Blocking / 补签字

## 4. 工具与命令

- **评审清单**：`templates/review-checklist.md`（逐项勾选并记录意见）
- **前置校验**：`python scripts/check_tracker.py --node A5 --deps A1,A2,A3,A4`
- **基线冻结**：
  ```
  git add work/soc/docs/spec/ && git commit -m "spec v1.0 freeze"
  git tag spec-v1.0
  git log --oneline   # 确认基线
  ```
- **纪要工具**：Markdown 纪要（问题列表、结论、责任人、签字栏）
- **决策留档**：评审签字记录写入 `state/state-decisions.md`（本实验的对照数据）
