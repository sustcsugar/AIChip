# 节点 F1：约束签核评审

> 阶段 F STA 时序收敛 | 归属 agent：signoff-agent | 对应 skill：`.opencode/skills/node-f1-constraint-review/`

## 1. 节点目的与范围

对 E1 产出的 SDC 做签核级质量评审：完整性（所有时钟/IO/端点被约束）、覆盖率（无遗漏路径）、异常路径声明的正确性（不掩盖真实时序问题）。签核 SDC 是整个 STA 流程（F2/F3）的约束基线，此节点同时是时序收敛环（Loop 2）的第一个关口。

范围：SDC 静态质量评审 + 工具化覆盖率检查（`check_timing`/`report_checks -unconstrained_endpoints` 等），形成签核版 SDC 与评审记录。不包含 STA 时序计算（F2）与违例修复（F3）。

## 2. 输入产物（前置条件）

- [ ] 前序节点产物（由 `state/state-tracker.md` 确认 passed）：E1 约束开发（评审通过）、E5 LEC、E4 DRC、E6（如执行）
- [ ] E1 `top.sdc`（评审对象）、`sdc_consistency.md` 核对表
- [ ] A2 系统规格（时钟频率/IO 指标）、A3 接口规格、B1 系统架构（时钟方案）
- [ ] C5 CDC 报告（确认跨域路径声明依据）
- [ ] E3 门级网表与 E2 库（用于 `check_timing` 等工具化检查）

## 3. 执行步骤

### Plan
- 明确评审维度：时钟完整性、IO 完整性、异常路径正确性、覆盖率、数值合理性
- 明确产物清单：SDC 评审报告、签核版 SDC、约束覆盖率表

### Execute
- 时钟完整性：逐时钟核对 `create_clock`/`create_generated_clock`，检查所有生成时钟的 `-source`/`-master_clock` 指向正确，频率/分频比与规格一致
- IO 完整性：`all_inputs`/`all_outputs` 逐一核对 delay/load/drive 约束，无遗漏端口
- 异常路径：核对每个 CDC 域有 `set_clock_groups`/`set_false_path`；每个 `set_false_path`/`set_multicycle_path` 有书面依据；`set_case_analysis` 与实际模式一致
- 覆盖率工具化检查：`check_timing`（缺约束/悬空）、`report_checks -unconstrained_endpoints`、`report_clock_groups`；`set_clock_groups` 未覆盖的跨域用 `report_clock_interaction` 复核
- 数值合理性：uncertainty 预算（skew+jitter+margin）、input/output delay 与 A2/A3 对齐；`set_max_transition/cap/fanout` 与库缺省核对
- 冻结签核版 SDC：评审通过后复制为 `soc_top.sdc`，此后任何修改走版本化变更记录

### Measure
- 收集：时钟覆盖率、IO 覆盖率、异常路径声明数与依据齐备率、`check_timing` 阻塞性警告数

### Judge
- 时钟/IO 覆盖率 100%，异常路径全部有依据，无 unconstrained endpoint
- 数值合理（与规格/工艺一致），无「掩盖型」声明（如把真实路径误标 false）
- 不满足 → 回 E1 修订 SDC 后重评；满足 → 进入质量门（人工签字）

## 4. 工具与命令

- 工具：Primetime（PrimeTime）为主执行工具化检查，配合 DC/GENUS `check_timing`；商用工具由人机协同脚本驱动
- 覆盖率检查：
  - `read_verilog top_netlist.v`；`link_design`；`read_sdc soc_top.sdc`；`update_timing`
  - `check_timing -verbose`（缺约束/未约束端点）
  - `report_checks -unconstrained_endpoints`（未约束端点清单）
  - `report_clock_groups`、`report_clocks`、`report_generated_clocks`
  - `report_clock_interaction -significant_digits 2`（跨时钟交互，确认未声明域已声明）
  - `all_inputs`/`all_outputs`/`all_clocks` 属性遍历生成覆盖率表
- 数值核查：`report_clock_uncertainty`、`report_ports -verbose`、`get_attribute` 遍历 delay/load
- 自定义脚本：`scripts/check_sdc_quality.py` — 解析 SDC 与规格，自动比对时钟/IO/异常路径覆盖率

## 6. 收敛判据（DoD）

**约束质量确认**，判定方法：
- 时钟覆盖率 100%（每个规格时钟有定义且频率/关系正确）
- IO 覆盖率 100%（无 unconstrained input/output/endpoint，`report_checks -unconstrained_endpoints` 为空）
- 异常路径声明与 CDC/架构文档一一对应，依据齐备
- 签核版 SDC 冻结，变更走版本化记录

## 7. 质量门与签字

- 质量门类型：人工签字（人工评审签字）
- 评审重点：约束完整性、异常路径声明、数值合理性、覆盖率检查证据
- 未签字不得进入 F2 STA
