# SOP — 人机协同芯片开发标准作业流程

> 本文档是本实验的总纲：流程模型、收敛关口、节点索引。
> 每个节点的详细定义见 `doc/<节点ID>-<名称>.md`。
> 设计基线见 `doc/设计/2026-08-19-ai-chip-sop-design.md`。

## 1. 实验定义

- **目标**：验证"人与 AI 协同，完整开发一款可收敛的芯片"
- **收敛标准**：功能正确（覆盖率达标 + 回归全绿）+ 综合后时序收敛（STA WNS/TNS ≥ 0）
- **工具链**：混合 — RTL 验证用开源（Verilator/cocotb/UVM），后端用商用（DC/GENUS/Primetime）
- **芯片形态**：SoC + IP 复用（子系统/子模块为独立可复用项目）

## 2. 流程模型：收敛环迭代

```
治理层 G0：状态跟踪 / 收敛看板 / 里程碑 / 评审门控（贯穿全程）
  │
  ▼
A 需求与规格 → B 架构与集成规划      （规划期，文档密集）
  │
  ▼
C 微架构与 RTL ←→ D 验证             （功能收敛环 Loop 1）
  │                    │   bug 反馈
  ▼  关口1：功能收敛（D7 验证签核）
E 综合与约束 ←→ F STA 时序           （时序收敛环 Loop 2）
  │                    │   违例修复/约束校正（可回退改 RTL）
  ▼  关口2：时序收敛（F5 签核）
G 签核与交付 → H 物理设计（可选扩展）
```

每阶段内部：**Plan → Execute → Measure → Judge（收敛判据）→ Iterate / Release**。

## 3. 强制收敛关口

| 关口 | 位置 | 判据 | 越过条件 |
|------|------|------|---------|
| 关口1：功能收敛 | D7 验证签核 | 功能+代码覆盖率达标、回归全绿、无未决 RCR | 人工签字 |
| 关口2：时序收敛 | F5 时序签核 | 所有角下 WNS/TNS ≥ 0（或达标） | 人工签字 |

关口前必须停下等人工签字；未签字不得进入下一阶段。

## 4. 两层项目模型

- **IP 项目层**：`work/ip/<ip>/`，独立收敛单元（止于 D7 签核），发布 tag。
- **SoC 项目层**：`work/soc/`，集成收敛单元，经 `ip_manifest.json` 固定 IP 版本（只读消费）。
- **验证策略**：早期集成用 `mode: model`，签核前切 `mode: rtl`。
- **纪律**：不得修改 manifest 锁定的 IP 源码（ip-discipline skill）。

## 7. 节点详章统一结构

每个 `doc/<节点ID>-<名称>.md` 固定包含：

1. 节点目的与范围
2. 输入产物（前置条件）
3. 执行步骤（Plan → Execute → Measure → Judge）
4. 工具与命令
5. 人机职责分配（AI 全自动 / AI 产出人审 / 人机协同）
6. 收敛判据（DoD）
7. 质量门与签字
8. 输出产物（后置交付）
9. 对应 skill 与 agent
