# 节点 C2：模块接口契约

> 阶段 C | 归属 agent：rtl-agent | 对应 skill：`.opencode/skills/node-C2-module-interface-contract/`

## 1. 节点目的与范围

**目的**：将 C1 微架构中定义的端口与握手正式化为无歧义的**模块接口契约**：端口信号清单、位宽与方向、时钟/复位域、时序约束、协议约束（AXI/APB/流式握手/中断/异步复位释放）。契约是 C3 编码、C6 模块级 smoke、D 阶段 VIP/断言开发、以及多模块联调对齐的共同基准，杜绝"同名不同义、位宽不匹配、方向冲突、时钟域未标注"等歧义。

**范围**：
- 覆盖所有**自研模块**（含 glue）的外部接口（对 SoC 顶层、对其他自研模块、对复用 IP 的接口连接）。
- 复用 IP 的接口契约已在 C0 验证（`interface-contract.md`），本节点只定义 SoC 侧对它们的**连接契约**（顶层连线规则）。
- 系统级互联/仲裁细节（若跨模块）可在契约中引用，正式互联描述归 C7 集成。

## 2. 输入产物（前置条件）

- [ ] C1 微架构规格（passed）：各模块接口与端口初版、握手与状态机描述
- [ ] A3 接口规格（passed）：系统级引脚/总线/中断/存储映射规格
- [ ] B2 地址映射（passed）：寄存器地址分配
- [ ] B3 总线与互联选型（passed）：AXI4/AXI4-Lite/APB 协议版本、位宽、ID 宽度
- [ ] C0 IP 接入与合同验证（passed）：复用 IP 接口合同已固定
- [ ] `.opencode/skills/node-C0-ip-adoption/assets/templates/ip-contract.md`（接口描述参考格式）

## 3. 执行步骤

### Plan
- 从 C1 微架构提取每个模块的端口清单与握手描述。
- 建立**跨模块接口对**清单：驱动模块端口 ↔ 负载模块端口（含跨时钟域接口对、握手对 valid/ready、请求/应答）。

### Execute
- 对每个端口完成契约化定义，四项属性必须齐全：**方向**、**位宽**、**所属时钟域**、**时序/协议描述**。
- 对协议类接口（AXI 读/写通道、APB、流式握手）写明完整信号时序：valid/ready 关系、通道间依赖（如 AXI AW/W/B 通道顺序约束）、背压与反压机制、突发长度与对齐约束。
- 对控制类信号（复位、使能、中断）写明：极性、同步/异步、与时钟沿的关系、中断电平/脉冲与确认机制。
- 对跨时钟域接口（C1 已标注）写明同步方案与约束（对应 C5），作为 CDC 检查的输入。
- 执行歧义检查：模块内端口命名唯一、无位宽不匹配、无方向冲突；跨模块接口对两两匹配（驱动/负载位宽、方向一致）；与 C1 端口清单、A3 接口规格、B2 地址映射一致性核对。
- 契约文档中每个接口链接回 C1 微架构对应章节。

### Measure
- 每模块：端口总数、协议接口数、CDC 接口数、与 C1 端口清单差异数。
- 歧义检查结果：命名冲突数、位宽不匹配数、方向冲突数、时钟域未标注数。
- 跨模块接口对匹配核验：驱动/负载对全对齐。

### Judge
- 歧义检查全部清零（见第 6 节判定方法）。
- 不满足 → 修正契约（同步修订 C1 相应章节），重新检查；满足 → 提交评审（质量门：评审）。

## 6. 收敛判据（DoD）

**DoD：接口契约无歧义。**

可操作判定方法：
1. 每个端口四项属性（方向/位宽/时钟域/时序）齐全，契约内无 `TBD`。
2. 模块内无命名冲突；契约端口清单与 C1 微架构端口清单**零差异**。
3. 跨模块接口对：每个驱动的位宽/方向与对应负载完全匹配，无悬空或未定义连接。
4. 协议接口（AXI/APB/流式）时序约束明确：valid/ready、通道依赖、背压、突发对齐均有文字或波形图定义。
5. 跨时钟域接口均标注同步方案，与 C5 检查输入一致。
6. 与 A3 接口规格、B2 地址映射一致性核对通过（`check_ports.py` 输出零差异）。
7. 评审通过：评审 checklist 全勾选，无未闭环问题。
