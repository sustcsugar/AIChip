# 节点 G3：基线归档

> 阶段 G 签核与交付 | 归属 agent：signoff-agent | 对应 skill：`.opencode/skills/node-G3-baseline-archive/`

## 1. 节点目的与范围

在 G1 交付包与 G2 收敛双签核通过后，将收敛态冻结为**正式 release 基线**：打 git release tag、更新版本信息、归档基线快照，保证任何时刻可精确复现该收敛版本。

范围：
- 为 RTL / netlist / 约束 / 文档 / 交付包打统一的 release tag（含 IP 与 SoC 两层）。
- 冻结基线（freeze）：tag 之后禁止任何非经评审的改动。
- 归档基线快照：将交付包、收敛报告、签核证据一并挂到 tag 下。
- 发布说明（RELEASE_NOTES）与版本回滚指南。

## 2. 输入产物（前置条件）

- [ ] G2 收敛双签核签字（`state/tracker.md` 中 G2 = passed）
- [ ] G1 完整交付包（`DELIVERY_MANIFEST.json` + 归档包）
- [ ] 收敛报告（G2 输出）
- [ ] git 仓库：SoC 仓库 + 各 IP 仓库，当前分支已提交干净（`git status` 干净）
- [ ] `soc/ip_manifest.json`（版本号将随基线更新）
- [ ] 版本命名规范（如 `<soc>_vX.Y`，IP 用 `<ip>_vX.Y`）

## 3. 执行步骤

### Plan
- 确认 G2 已签字、工作区 git 干净、无未提交变更。
- 确定基线版本号（与 G1 包内 `<soc_version>` 一致），评审 tag 命名与版本号递增规则。

### Execute
- 在工作区执行最后一次确认：`git status` / `git diff` 为空；RTL 与 C7 freeze tag 一致。
- 打 tag（SoC 主仓）：
  - `git tag -a <soc_version> -m "<release notes 摘要>"`
  - `git push origin <soc_version>`（推送 tag）
- IP 层：若 IP 有改动，先在 IP 仓打对应 tag（遵守 ip-discipline，不改动被锁定的 IP 源码）。
- 归档快照：将交付包、收敛报告、签核证据加入归档并引用到 tag 的注释中。
- 生成/更新 `RELEASE_NOTES.md`（变更摘要、新增能力、已知限制、复现步骤）。
- 更新 `soc/ip_manifest.json` 中 soc_version，记录基线日期与 commit hash。

### Measure
- 记录：tag 名、commit hash（`git rev-parse HEAD`）、tag 时间戳、归档包 SHA-256、参与归档的文件数。
- 统计：自上一基线以来的变更（commit 数、文件数、行数）。

### Judge
- 对照第 6 节收敛判据：tag 存在且指向 HEAD、工作区干净、归档完整、版本号一致。
- 不满足 → 修正重打（补 tag/补归档/补版本号）；满足 → 进入质量门（人工签字）冻结基线。

## 4. 工具与命令

- 打 tag：`git tag -a <soc_version> -m "<msg>" && git push origin <soc_version>`
- 查看 tag 与 hash：`git show-ref --tags` / `git rev-parse <tag>`
- 工作区干净检查：`git status --porcelain`（空输出即干净）
- 与 freeze tag 比对：`git diff --stat <c7_tag>`（空）
- IP tag：`cd work/ip/<ip> && git tag -a <ip>_vX.Y -m ... && git push origin <ip>_vX.Y`
- 归档：将 `work/soc/deliverables/<soc_version>/` 复制到归档目录或附到 release 资产；校验 `sha256sum -c`。
- 版本回滚：`git checkout <上一基线 tag>`，参考 RELEASE_NOTES 的回滚指南。

## 6. 收敛判据（DoD）

**DoD：基线冻结。**

可操作判定方法：
- tag 有效：SoC release tag 已创建并推送，`git show-ref --tags` 可见，指向当前签核 HEAD。
- 工作区干净：`git status --porcelain` 为空，无未提交/未跟踪变更。
- 与冻结版本一致：RTL 与 C7 freeze tag 零差异；netlist/约束/报告与 G1/G2 交付版本一致。
- 归档完整：交付包 + 收敛报告 + 证据均可由 tag 关联复现，`sha256sum -c` 通过。
- 版本号一致：`ip_manifest.json` 的 soc_version 与 tag 名、交付包目录名一致。
- 冻结生效：tag 创建后无绕过评审的改动；如需修改必须走新版本（升版本号再打 tag）。
- 判定结论：全部满足 → 基线冻结成立；否则修正后重打。

## 7. 质量门与签字

- 质量门类型：人工签字（基线冻结确认书 + RELEASE_NOTES 签字）。
- 未签字不得将基线视为正式冻结、不得对外交付或进入 H 阶段（如启用）。
