# 节点 C1：微架构规格

> 阶段 C | 归属 agent：rtl-agent | 对应 skill：`.opencode/skills/node-C1-microarch-spec/`

## 1. 节点目的与范围

**目的**：为每个自研模块（含 SoC glue 逻辑：复位生成、时钟管理、中断仲裁、pinmux）编写微架构规格，把 B 阶段架构级的模块划分细化为可编码的硬件描述：状态机、握手协议、流水线结构、寄存器定义（Regmap）、数据通路、跨时钟域与关键时序。该文档是 C3 编码的唯一依据，也是 D 阶段验证计划（vplan）的参考。

**范围**：
- 每个**自研模块**一份微架构规格（`.opencode/skills/node-C1-microarch-spec/assets/templates/spec-microarch.md` 的 8 节结构）。
- **复用 IP 不写微架构**：其内部设计文档归属 IP 项目自身，SoC 侧只消费其接口合同（C0）与 manifest 版本。
- 不包含系统级集成描述（属 C7）；不包含详细端口时序图（属 C2 接口契约），本节点只给出接口与端口初版作为 C2 输入。

## 2. 输入产物（前置条件）

- [ ] A2 系统规格（passed）：功能与性能指标（时延/吞吐/频率目标）
- [ ] B1 系统架构（passed）：模块划分、顶层框图、数据流
- [ ] B2 地址映射（passed）：寄存器地址分配与访问权限
- [ ] B3 总线与互联选型（passed）：AXI/APB 协议版本与位宽
- [ ] C0 IP 接入与合同验证（passed）：复用 IP 已接入并 pin 版本
- [ ] `.opencode/skills/node-C1-microarch-spec/assets/templates/spec-microarch.md` 微架构模板
- [ ] B5 架构评审（passed）：架构冻结，模块边界确定

## 3. 执行步骤

### Plan
- 从 B1 模块划分列出全部待写微架构模块清单（自研功能模块 + glue 模块）。
- 按依赖顺序排序：先写无依赖的叶子模块，再写依赖模块；glue（复位/时钟/中断仲裁/pinmux）最后写，因为其接口依赖各功能模块的时钟/复位/中断需求汇总。
- 为每个模块确定：时钟域、复位策略、挂载总线（来自 B2/B3）。

### Execute
- 对每个模块按 `.opencode/skills/node-C1-microarch-spec/assets/templates/spec-microarch.md` 的 8 节展开：
  1. **模块概述**：功能定位、在系统中的位置、挂载总线。
  2. **接口与端口**：端口列表（信号名、宽度、方向）、时钟/复位/使能。
  3. **寄存器定义（Regmap）**：偏移、名称、R/W、位宽、复位值、描述；与 B2 地址映射逐条对齐。
  4. **状态机**：mermaid 状态转移图 + 状态表（每个状态的进入条件、退出条件、相关动作）；显式定义复位状态、空闲态与非法状态处理。
  5. **数据通路与流水线**：流水线级数、各级功能、valid/ready 握手时序（含气泡/停顿/背压行为）。
  6. **跨时钟域**：时钟域划分、同步策略（2-flop/握手/异步 FIFO/格雷码），对应 C5 检查项。
  7. **关键时序**：关键路径描述、时延/吞吐约束、时钟频率假设。
  8. **接口契约链接**：标注对应 C2 模块接口契约文档（C2 完成后回填链接）。
- 状态机、流水线图用 mermaid 绘制，保证可渲染、可评审。
- 每个模块自检：状态机无不可达状态、无缺转移条件；握手无死锁路径；Regmap 与 B2 无冲突。

### Measure
- 每模块度量：状态机状态数、转移条件覆盖、流水线级数、寄存器数、时钟域数、CDC 接口数。
- 文档完整性自检：8 节齐备、无 TBD 占位符、mermaid 图可渲染。
- 一致性核验：Regmap 与 B2 地址映射表逐条比对结果。

### Judge
- 对照 DoD 逐项检查（见第 6 节）。
- 不满足 → 修正重写对应章节，重新自检；满足 → 提交评审（质量门：评审）。

## 4. 工具与命令

- 文档格式：Markdown + Mermaid（状态机图、流水线时序图），按节点 skill 规定的目录结构与命名存放。
- **寄存器与地址描述**：Accellera **SystemRDL 2.0** 为地址与寄存器的**唯一事实源**（按 `AIFlow/state/state-decisions.md` 中工具链决策执行）；工具链 PeakRDL（`pip install peakrdl peakrdl-regblock peakrdl-c-header peakrdl-html`，随工具链环境就绪）：
  - 顶层 SystemRDL 文件定义全局地址空间 + 全部外设寄存器（addrmap 嵌套例化），替代 B2 阶段的 YAML 地址映射与 Markdown 寄存器表格
  - 对拍校验：`peakrdl html` 生成寄存器清单，与 B2 阶段冻结的地址映射事实源逐条比对（基址/大小一致）；通过后 YAML + 地址检查脚本退役
  - 基址常量生成：`peakrdl c-header` 替代原 YAML 派生的 C 头，`peakrdl regblock` 替代原 YAML 派生的 RTL 常量包
- 模板：`.opencode/skills/node-C1-microarch-spec/assets/templates/spec-microarch.md`
- 评审工具：review-gate skill + `.opencode/skills/_shared/templates/review-checklist.md`
- 一致性辅助检查（可选）：`AIFlow/scripts/check_regmap.py`（如存在）

## 6. 收敛判据（DoD）

**DoD：状态机/握手/流水线描述完整，可指导编码。**

可操作判定方法：
1. 每个模块 8 节齐备，全文无 `TBD`/`TODO` 占位符。
2. **状态机完整**：mermaid 图中所有状态可达（从复位态可达任意状态，无孤立状态）；每个状态转移条件为确定布尔表达式，无歧义；复位状态与非法状态处理有定义。
3. **握手完整**：valid/ready 时序有描述（组合或寄存输出、停顿、背压、死锁规避条件），无未定义握手路径。
4. **流水线完整**：级数、各级功能、气泡/停顿插入机制明确；吞吐与时延与 A2 指标一致。
5. **Regmap 完整**：每寄存器有偏移/位宽/复位值/访问属性，以 SystemRDL `.rdl` 为唯一事实源（地址+寄存器合一，按 `AIFlow/state/state-decisions.md` 中工具链决策执行），与 B2 阶段冻结的地址映射逐条对拍一致（通过后 YAML 退役），无冲突。
6. **CDC 标注**：跨时钟域接口均标注同步方案（对应 C5）。
7. 评审通过：`review-checklist.md` 全部勾选，评审纪要无未闭环问题。
