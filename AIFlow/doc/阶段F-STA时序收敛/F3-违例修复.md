# 节点 F3：违例修复

> 阶段 F STA 时序收敛 | 归属 agent：signoff-agent | 对应 skill：`.opencode/skills/node-f3-fix-violations/`

## 1. 节点目的与范围

修复 F2 列出的时序违例，使全 scenario 的 WNS/TNS ≥ 0（或达到与人类约定的达标值），完成时序收敛环（Loop 2）的核心迭代。修复手段按代价从小到大分层：约束校正 → 网表级修复（重综合/ECO）→ 回退 C 阶段改 RTL。

范围：基于 F2 违例清单逐条定位与修复，重跑 STA 确认；涉及 RTL 修改时协调 orchestrator 回退 C 阶段收敛环。不包含功耗估算（F4）与签核（F5）。

## 2. 输入产物（前置条件）

- [ ] 前序节点产物（由 `AIFlow/state/state-tracker.md` 确认 passed）：F2 STA 分析（检查通过）、F1 签核 SDC
- [ ] F2 违例清单 `sta_violations_max.rpt`/`sta_violations_min.rpt` 与汇总表
- [ ] E3 网表、E2 库（全部角）、F1 签核 SDC
- [ ] C 阶段微架构规格（用于评估 RTL 级修复空间：流水级、组合深度）

## 3. 执行步骤

### Plan
- 按违例分类定修复策略优先级：约束校正（低代价）→ 网表修复（中代价）→ RTL 回退（高代价）
- 明确产物清单：修复后的网表/约束/报告、修复记录、回退请求（如有）

### Execute
- **层次 1 — 约束校正**：对「约束假象」类违例（约束过紧、时钟关系声明错误、缺失 multicycle、case analysis 错误、ignored timing 误设）回 F1 修订 SDC（走 sdc_changelog 版本化），常见修正命令：
  - `set_multicycle_path -setup 2`（正确握手关系）、`set_false_path`/`set_clock_groups` 校正（需依据）、`set_clock_uncertainty` 校准（有工艺依据）、`set_case_analysis` 修正
- **层次 2 — 网表级修复**（约束正确但仍违例）：
  - 尺寸调整/缓冲：对 max_transition/capacitance 类违例插缓冲器（`insert_buffer`）；对 setup 违例用更小驱动或 `size_cell`
  - 重综合优化：回到 E3 以更优策略重综合（`compile_ultra -timing`、调整 effort、启用边界优化、放宽 area 目标），再用 E5 LEC 复验
  - 局部 ECO：`eco_netlist`/`eco_design` 处理少量关键单元替换（网表一致后需重跑 LEC）
- **层次 3 — 回退 RTL**：若违例源于结构问题（组合逻辑链过深、流水级不足、跨域同步不足），协调 orchestrator 回退 C 阶段收敛环：改 RTL → 重新 D 验证 → 重新 E 综合/LEC → 回到 F2/F3 重测（每次回退在 `AIFlow/state/state-decisions.md` 记录）
- 每轮修复后重跑受影响 scenario 的 STA（F2 流程），比对 WNS/TNS 变化

### Measure
- 收集：修复前后各 scenario 的 WNS/TNS、违例路径数、修复措施清单与代价（是否动 RTL）、迭代轮次

### Judge
- 全部 scenario 的 WNS/TNS ≥ 0（或达到约定的达标值）
- 约束改动均走 changelog 且有依据；网表改动后 E5 LEC 复验通过
- 若改 RTL：C 阶段重新收敛（Loop 1）+ E 阶段重新执行后方可回到本节点
- 不满足 → 继续下一轮修复；满足 → 进入质量门（检查）

## 4. 工具与命令

- 工具：PrimeTime（定位与复验）、DC/GENUS（网表级修复）、Formality/Conformal（复验）；商用工具由人机协同脚本驱动
- 定位：
  - `report_checks -path_delay max -slack_lesser_than 0 -path_type full -max_paths <n>`（setup 违例路径）
  - `report_checks -path_delay min -slack_lesser_than 0 -path_type full`（hold 违例）
  - `report_timing -delay_type max -through <net/cell>` 定位关键组合链
  - `report_design_rules` 定位 transition/cap 类违例
- 约束校正（回 F1）：
  - `set_multicycle_path`、`set_false_path`、`set_clock_groups`、`set_clock_uncertainty`、`set_case_analysis`
- 网表修复（DC/GENUS）：
  - DC：`insert_buffer`、`size_cell`、`compile -only_design_rule`；全量重综合 `compile_ultra -timing`
  - GENUS：`insert_buffer`、`resize_cell`、`opt_design`
  - ECO：`eco_netlist -write_eco_changes`（PrimeTime）/ `eco_design`（Conformal/DC）
- 复验：重跑 E5 LEC（`verify`/`compare`）+ E4 DRC + F2 STA
- 记录：`AIFlow/scripts/parse_sta.py` 输出修复前后对比表；`AIFlow/state/state-decisions.md` 记录 RTL 回退决策（orchestrator 写入）

| RTL 回退决策 | 人类 + orchestrator | 人机协同 | 必须确认：协调 orchestrator 回退 C 阶段收敛环（改 RTL→重验证→重综合→重 STA），并在 decisions 记录 |

| 质量门检查签字 | 人类 | 人工 | 必须签字 |

## 6. 收敛判据（DoD）

**WNS/TNS ≥ 0（或达标）**，判定方法：
- 全部 scenario 复测后 WNS ≥ 0 且 TNS = 0（口径与 F2 一致）
- 若与人类约定「达标值」（如预留 margin 下的目标），按约定判定并记录
- 约束改动全部走 changelog，网表改动后 E5 LEC 复验 pass、E4 DRC clean
- 如涉及 RTL 回退：C 阶段 Loop 1 与 E 阶段已重新收敛，再回到本节点复验

## 7. 质量门与签字

- 质量门类型：检查（check）
- 检查重点：WNS/TNS 达标、修复措施可追溯（changelog/decisions）、LEC/DRC 复验通过
- 未签字不得进入 F4/F5
