# 节点 D3：定向测试

> 阶段 D 验证 | 归属 agent：verify-agent | 对应 skill：`.opencode/skills/node-D3-directed-tests/`

## 1. 节点目的与范围

开发并运行定向测试用例。针对 D1 vplan 中标记为"定向"的测试点，编写针对性激励与参考检查，验证明确的单点功能行为，建立功能收敛的基线。

范围：
- 两级环境定向用例：模块级 `verif/block/<mod>/tests/` + 系统级 `verif/sys/tests/`。
- 每个定向用例对应一个明确 TP 与检查点（scoreboard / 参考模型 / 断言交互）。
- 发现 bug 时以 RCR（验证缺陷记录）反馈 C 阶段（功能收敛环 bug 反馈回路）。

## 2. 输入产物（前置条件）

- [ ] D2 TB 环境 passed（编译运行闭环可用）
- [ ] D1 vplan passed（提取"定向"类型 TP 清单）
- [ ] C1 微架构规格 passed（确定各功能的预期行为，用于写检查点）
- [ ] C2 模块接口契约 passed（激励时序、握手序列）

## 3. 执行步骤

### Plan
1. 从 vplan 提取 `测试类型=定向` 的 TP，按模块/子系统分组。
2. 排出用例清单与优先级（关键路径 > 一般功能 > 边界单点）。
3. 为每个用例确定检查点：预期结果来源（规格值、参考模型、属性）。

### Execute
4. 逐用例编码：激励序列（cocotb coroutine 或 UVM sequence）+ 参考检查（scoreboard 断言）。
5. 维护 testplan 映射表：TP ↔ 用例文件 ↔ 检查点。
6. 运行定向用例集（block 全量 + sys 定向冒烟）。
7. 失败时先判根因：TB 缺陷 / 用例缺陷 / RTL bug（RTL bug 登记 RCR 并通知 rtl-agent 修复）。

### Measure
8. 记录度量：用例总数、通过/失败数、每个定向 TP 的 hit 情况。
9. 运行 `python AIFlow/scripts/check_tracker.py --node D3`。

### Judge
10. 对照收敛判据逐项检查（见第 6 节）。
11. 不满足 → 修正用例 / 等 RTL 修复后重测；满足 → 进入质量门。

## 4. 工具与命令

- **cocotb 用例**：每个 TP 一个 test 函数，基于 `cocotb.test()` 装饰器：
  - 单用例：`SIM=verilator make TESTCASE=test_uart_rx`
  - 全量：`SIM=verilator make`
  - 波形：`WAVES=1 make` → `.fst`，gtkwave 打开。
- **UVM 用例**：
  - 运行：`vvp sim.out +UVM_TESTNAME=test_xxx`（先 `iverilog -g2012` 编译，见 D2）。
  - 报告：UVM `*_fatal` / `*_error` 计数归零即通过。
- **参考检查**：Python 参考模型（cocotb，模块内比较）、scoreboard（UVM）、`assert` 语句。
- **RCR 登记**：`AIFlow/state/` 下 RCR-<id>.md 或 RCR 汇总表（格式见 D7 第 4 节）。
- 状态校验：`python AIFlow/scripts/check_tracker.py --node D3`。

## 6. 收敛判据（DoD）

**定向用例全过。**

可操作判定方法：
- 所有定向用例通过：cocotb `Passed` / UVM `0 errors / 0 fatal`，无用例超时或挂死。
- vplan 中 `测试类型=定向` 的 TP **100%** 有对应用例（TP ↔ 用例映射表无缺口）。
- 新发现的 RTL bug 均已登记 RCR 并关联用例，阻塞用例的修复状态已跟踪。
- 定向用例对功能覆盖点的 hit 记录不为空（为 D6 覆盖率收敛贡献基线）。
- `python AIFlow/scripts/check_tracker.py --node D3` 通过。
