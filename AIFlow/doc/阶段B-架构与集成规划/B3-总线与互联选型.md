# 节点 B3：总线与互联选型

> 阶段 B | 归属 agent：arch-agent | 对应 skill：`.opencode/skills/node-b3-bus-interconnect/`

## 1. 节点目的与范围

选择总线协议（AXI4 / AXI4-Lite / AHB / APB / NoC 等）与互联拓扑（crossbar / AXI NIC / 共享总线 / NoC mesh），并给出量化依据：带宽、时延、并发度、面积、功耗、可综合性、工具链与开源/商业 IP 支持度。产出互联架构说明与选型证据链。

范围：
- 协议选择：高性能口（存储控制器 / CPU）用 AXI4，低速外设（uart/gpio/timer）用 APB，可加 AXI4-Lite 配置口
- 拓扑选择：crossbar / NIC / 菊花链共享总线 / NoC
- 桥接方案：AXI↔APB 桥、时钟域 / 位宽转换
- 每个主 → 从口的带宽、时延、并发需求及分配

不涉及：地址窗口分配细节（B2，此处只消费其结果）；模块内部总线。

前置校验命令：`python AIFlow/scripts/check_tracker.py --node B3`

## 3. 执行步骤

### Plan
- 建立主从带宽 / 时延需求表：每个主 → 从对的峰值 / 平均带宽、有效载荷率、时延上限
- 列出候选协议与候选拓扑（含开源与商业选项）

### Execute
- 计算需求：逐对带宽、总聚合带宽、时延预算分配（传输 + 仲裁 + 排队）
- 建立协议对比矩阵：AXI4（乱序 / outstanding / 突发）、AXI4-Lite、AHB（流水）、APB、NoC——按带宽 / 面积 / 复杂度 / 工具链打分
- 建立拓扑对比矩阵：crossbar、AXI NIC、菊花链共享总线、NoC——按并发度 / 面积 / 功耗 / 时延打分
- 匹配规则：低速外设 → APB 经桥；存储控制器 → 独立高带宽口；多主并发 → crossbar / NIC
- 估算互联面积与功耗增量（每口 / 每仲裁器成本），作为量化依据之一

### Measure
- 聚合带宽余量：互联可提供带宽 ≥ 需求 × 1.2（20% 安全系数）
- 最坏路径时延 vs 规格上限
- 面积 / 功耗增量 vs B4 预算（粗核）

### Judge
- 对照 DoD（选型有量化依据，满足带宽 / 时延需求）逐项检查
- 对比矩阵每个候选至少 3 项量化指标，推荐项有完整证据链，无"拍脑袋"
- 不满足 → 换候选重算；满足 → 进入质量门（评审）

## 4. 工具与命令

- 带宽 / 时延计算模型：`AIFlow/scripts/bw_latency_model.py`（YAML 需求 → 逐对带宽、聚合带宽、时延、余量）
  - 运行：`python AIFlow/scripts/bw_latency_model.py --req <带宽需求YAML文件> --report <报告输出文件>`
- 对比矩阵：协议对比矩阵与拓扑对比矩阵（按节点 skill 规定的目录与命名）
- 复用 IP 接口核对：读 `ip/<ip>/AIFlow/doc/interface.md`，确认每个 IP 的总线接口类型与位宽
- 开源 / 商业互联核调研：核对 AMBA 协议规范、开源 AXI 核（如 verilog-axi）的功能与许可证
- 结果复验：将聚合带宽需求灌入 B4 模型核对总预算

## 6. 收敛判据（DoD）

DoD：选型有量化依据，满足带宽 / 时延需求。

可操作判定方法：
- 每个主 → 从对带宽需求 ≤ 分配口带宽 × 0.8（预留 20%）
- 聚合带宽 ≤ 互联可提供带宽，余量 ≥ 20%
- 最坏路径时延（传输 + 仲裁 + 排队估算）≤ 规格上限
- 对比矩阵每个候选有 ≥ 3 项量化指标；推荐项有明确证据链（数值 + 来源 + 假设）
- 选型结论与 B1 模块端口需求、B2 地址窗口一致
