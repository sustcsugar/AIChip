# 节点 G1：交付物打包

> 阶段 G 签核与交付 | 归属 agent：signoff-agent | 对应 skill：`.opencode/skills/node-G1-packaging/`

## 1. 节点目的与范围

本节点在 F5 时序签核（关口2）通过后，将芯片的全部交付物集中打包为**单一、完整、可复现、带校验和**的交付包，作为 G2 收敛双签核与 G3 基线归档的事实依据。

范围：
- 收集并核对交付物清单（RTL / netlist / SDC / 文档 / 各类报告）。
- 生成交付物清单（DELIVERY_MANIFEST）与逐项校验和（checksum）。
- 打包为归档文件（tar/zip 或目录快照），冻结打包时刻内容。
- 本节点**不做**任何收敛判定（属 G2），只保证"该有的都有、可追溯到源"。

## 3. 执行步骤

### Plan
- 读取 `AIFlow/state/state-tracker.md`，确认前置节点全部 passed、F5 已签字。
- 依据 SOP 第 5 节节点索引 + 项目目录骨架，生成交付物清单初稿（含每项来源路径与版本）。
- 明确打包目标目录 `deliverables/<soc_version>/` 与打包格式（先目录快照 + 再归档）。

### Execute
- 按清单逐项收集文件到 staging 目录，保持目录结构（`rtl/`、`netlist/`、`sdc/`、`docs/`、`reports/`、`verif/`）。
- 对每项生成 SHA-256 校验和，写入 `DELIVERY_MANIFEST.json`（含路径、版本、checksum、来源节点）。
- 交叉核对：manifest 内 IP 版本必须与 `ip_manifest.json` 一致；RTL 必须与 C7 freeze tag 一致（`git diff` 空）。
- 对清单中缺失/冗余/过期文件做差异报告，交由人工确认后再删补。
- 打归档包（`tar.gz`）并记录包级 SHA-256 与打包时间戳。

### Measure
- 统计：交付物总数、类型分布、总大小、checksum 数量、清单核对通过数。
- 记录：打包前后文件差异（新增/删除/修改）、与 freeze tag 的 diff 行数。

### Judge
- 对照第 6 节收敛判据逐项勾选：清单齐全、无缺项、checksum 一致、版本锁定、可复现。
- 不满足 → 修正重测（补齐/重取/重打包）；满足 → 进入质量门（检查）。

## 4. 工具与命令

- 文件清单生成：由 `AIFlow/scripts/build_manifest.py` 依据 `ip_manifest.json` + 目录骨架生成候选清单。
- 校验和：`sha256sum <file>`；批量：`find <staging> -type f -exec sha256sum {} \; > DELIVERY_MANIFEST.json`。
- 打包：`tar -czf <soc_version>.tar.gz -C <staging> .`（Windows 下可用 `tar.exe` 或 Python `shutil.make_archive`）。
- 版本一致性：`git diff --stat <c7_tag>`（RTL 无 diff）；`git log --oneline <ip_repo>` 核对 IP tag。
- 差异核对：`diff` / `comp` 对比 staging 与源目录。
- 完整性和可复现：解包到空目录后重跑 `sha256sum -c DELIVERY_MANIFEST.json` 验证。

## 6. 收敛判据（DoD）

**DoD：交付物清单齐全。**

可操作判定方法：
- 清单完整性：DELIVERY_MANIFEST 中每项与 SOP 要求的交付物一一对应，无缺项、无未知来源项。
- checksum 一致性：对每个文件执行 `sha256sum -c`，100% 通过，无校验失败。
- 版本锁定：RTL 与 C7 freeze tag `git diff` 为空；netlist 与 E5 LEC 所验版本一致；IP 版本与 `ip_manifest.json` 完全一致。
- 可复现性：交付包解包到全新目录后可独立完整复现（含脚本与版本信息）。
- 文档完备：规格/架构/微架构/接口/验证/STA 报告均在包内且与当前版本一致。
- 判定结论：全部满足 → 清单"齐全"成立，可进入 G2。

## 7. 质量门与签字

- 质量门类型：检查（人工核对交付物清单并签字确认"清单齐全"）。
- 未签字不得进入 G2 收敛双签核。
