# 节点 A4：需求可追溯矩阵

> 阶段 A | 归属 agent：spec-agent | 对应 skill：`.opencode/skills/node-A4-rtm/`

## 1. 节点目的与范围

- **目的**：建立"需求 REQ → 规格 SPEC/指标 → 测试点 TP"双向追溯矩阵（RTM），保证每条需求有规格承接、有测试点覆盖，且每条规格/测试点都有需求来源。
- **范围**：RTM 生成、正向/反向孤儿扫描、覆盖率度量、测试点初版派生（格式对齐 `.opencode/skills/node-D1-vplan/assets/templates/vplan.md`）。
- **不在本节点范围**：测试点细化与用例开发（D1 验证计划）。A4 产出测试点**初版**，D1 阶段据此细化并回填。
- **双向含义**：正向 = 需求 → 规格/测试点；反向 = 规格/测试点 → 需求。两个方向都要覆盖 100%。

## 2. 输入产物（前置条件）

- [ ] A1/A2/A3 输出通过（`AIFlow/state/state-tracker.md` 确认 A1、A2、A3 = passed）：
  - `docs/spec/spec-001-PRD.md`、`spec-002-use-cases.md`（REQ/SC/UC 来源）
  - `docs/spec/spec-NNN-system-spec.md`、`system-spec.csv`（规格条目与指标）
  - `docs/spec/spec-NNN-interface-spec.md`（接口条目，作为测试点输入之一）
- [ ] `.opencode/skills/node-D1-vplan/assets/templates/vplan.md` — 测试点格式参考（本节点只做初版，D1 细化）

## 3. 执行步骤

### Plan
- 确定追溯维度与矩阵结构：行 = 需求（REQ），列 = 规格条目（SPEC/指标）与测试点（TP）
- 定义三类链接：REQ↔SPEC、REQ↔TP、SPEC↔TP；明确 ID 引用规则（REQ-xxx / SPEC-xxx / TP-xxx）

### Execute
- **RTM 生成**：解析 A1/A2/A3 产物，自动建立 REQ ↔ SPEC/指标 ↔ TP 链接，输出矩阵表
- **测试点派生**：从每个场景 `UC` 派生测试点初版（正常/边界/异常），格式对齐 `.opencode/skills/node-D1-vplan/assets/templates/vplan.md`，每个 TP 标注对应 REQ
- **正向扫描**：无承接的孤儿需求（REQ 无 SPEC 或无 TP）
- **反向扫描**：无来源的孤儿规格/测试点（SPEC/TP 无 REQ 引用）
- **报告输出**：覆盖率统计 + 孤儿清单 + 缺口分析

### Measure
- 覆盖率统计：需求覆盖数/总需求、规格覆盖数/总规格、测试点覆盖数/总测试点
- 覆盖率 = 已覆盖条目数 / 总条目数（正向、反向分别统计）

### Judge
- 对照收敛判据：RTM 双向覆盖 100%
- 正向或反向存在孤儿 → 回到 Execute 补齐（补规格/补测试点/回补需求）；双向 100% → 进入质量门检查

## 6. 收敛判据（DoD）

- **RTM 双向覆盖 100%**

判定方法：
- 正向：每个 `REQ` 至少映射 1 条规格 + 1 个测试点，孤儿需求 = 0
- 反向：每个 `SPEC`/`TP` 至少映射 1 条 `REQ`，孤儿规格/测试点 = 0
- `AIFlow/scripts/a4_check_rtm.py` 输出双向覆盖率为 100%，无孤儿列表
- 测试点初版格式对齐 `.opencode/skills/node-D1-vplan/assets/templates/vplan.md`，可为 D1 直接承接（无格式返工）
