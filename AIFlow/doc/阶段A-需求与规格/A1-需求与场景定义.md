# 节点 A1：需求与场景定义

> 阶段 A | 归属 agent：spec-agent | 对应 skill：`.opencode/skills/node-A1-req-scope/`

## 1. 节点目的与范围

- **目的**：分析产品需求（立项 / 客户 / 市场输入），澄清需求歧义与缺失，定义典型使用场景与用例清单，输出 PRD 与需求基线。
- **范围**：覆盖 需求收集 → 需求条目化与分类 → 场景建模 → 用例派生 → 需求优先级评估 → open issue 管理。
- **不在本节点范围**：系统规格量化（A2）、接口定义（A3）、架构与总线选型（B 阶段）——本节点只产出"要做什么、在什么场景下用"，不产出"指标多高、接口长什么样"。

## 2. 输入产物（前置条件）

- [ ] 立项 / 需求输入已就绪（本节点为阶段 A 起点，无前序 SOP 节点依赖）
- [ ] 产品立项文档 / 市场与客户需求描述（原始需求输入，含目标市场、目标功耗/成本档位、必选功能）
- [ ] 客户访谈纪要 / 竞品分析 / 应用场景描述 / 性能初步要求
- [ ] `.opencode/skills/skill-scaffold/assets/node-template/node-doc-template.md`（节点详章模板）
- [ ] 复用 IP 意向清单（若有，参考 `.opencode/skills/node-C0-ip-adoption/assets/templates/ip-contract.md` 了解既有能力作为背景，不展开）

## 3. 执行步骤

### Plan
- 读取需求输入，识别需求边界、相互矛盾项与缺失信息，列出需要澄清的问题清单
- 明确本节点产物清单：PRD、场景清单、用例清单、需求优先级表、open issue 列表
- 定义需求分类维度：功能 / 性能 / 接口 / 功耗 / 成本 / 可测试性（DFT/调试）

### Execute
- **需求条目化**：每条需求赋予唯一 ID（`REQ-<n>`），记录来源、描述、接受准则；分类归档
- **场景建模**：定义典型使用场景 `SC-<n>`（运行条件、数据流路径、并发行为、性能要求），用 Mermaid 场景流程图表达
- **用例派生**：从每个场景导出用例 `UC-<feature>-NNN`，feature 为功能域短 slug（如 BOOT/UART/JTAG/SPI/IIC/PWM/GPIO/INT/BUS/PWR/DEMO），同一功能域内从 001 递增；覆盖 正常路径 / 边界路径 / 异常路径 三类
- **优先级评估**：按 Must / Should / Could 标记，记录依据
- **open issue 管理**：无法即时澄清的需求登记为 open issue（问题描述 / 影响范围 / 待答复角色），后续逐条关闭

### Measure
- 统计需求条目数、场景数、用例数、open issue 数
- 用例模式覆盖检查：正常 / 边界 / 异常 三类路径比例
- 映射检查：每个场景 `SC` 至少对应 1 个用例 `UC`；每个需求 `REQ` 至少被 1 个用例覆盖

### Judge
- 对照收敛判据：open issue 是否为 0；用例是否覆盖主要使用模式
- 不满足 → 回到 Execute 补充用例或发起需求澄清；满足 → 进入质量门评审

## 4. 工具与命令

- **文档工具**：Markdown（PRD / 场景 / 用例清单）、Markdown 表格（需求条目与优先级）、Mermaid（场景流程图）
- **版本追溯**：`git diff` / `git log --oneline` 确认变更范围
- **状态校验**：`python AIFlow/scripts/check_tracker.py --node A1` 核对看板状态
- **需求完整性校验脚本**（建议新增 `AIFlow/scripts/a1_check_req.py`）：
  ```
  python AIFlow/scripts/a1_check_req.py --prd docs/spec/spec-001-PRD.md --scen docs/spec/spec-002-use-cases.md
  # 输出：REQ/SC/UC 条目数、open issue 列表、未被任何 UC 覆盖的 REQ、无 UC 的 SC
  ```
- **表格工具（可选）**：CSV 导出需求清单，便于评审与跨节点引用（`REQ-xxx` ID 是 A2/A4 的引用键）

## 6. 收敛判据（DoD）

- **场景清单无未决 open issue**
- **用例覆盖主要使用模式**

判定方法：
- `AIFlow/scripts/a1_check_req.py` 输出 open issue 列表为空（计数 = 0）
- 每个 `SC` 至少映射 1 个 `UC`；每个 `REQ` 至少被 1 个 `UC` 覆盖（脚本输出遗漏列表为空）
- 用例清单明确涵盖 正常 / 边界 / 异常 三类路径，数量比例有记录
- `REQ-xxx` ID 全局唯一且命名规范，可供 A2/A4 追溯引用
