# 节点 A2：系统规格

> 阶段 A | 归属 agent：spec-agent | 对应 skill：`.opencode/skills/node-A2-system-spec/`

## 1. 节点目的与范围

- **目的**：编写系统规格书——功能规格 + 性能指标（Fmax / 吞吐 / 面积 / 功耗预算 / 时延），全部指标可量化、可测试、与 A1 场景对应。
- **范围**：功能模块清单与行为定义、性能指标表、设计约束（工艺/时钟/复位/电源）、可测试性要求、验收标准、需求追溯。
- **不在本节点范围**：具体引脚 / 总线 / 中断 / 地址映射（A3）、架构方案与选型（B 阶段）。本节点定义"指标多高、怎么测"，不定义"接口怎么连"。
- **输出参考**：`.opencode/skills/node-A2-system-spec/assets/templates/spec-system.md`，填写后存入 `docs/spec/`。

## 3. 执行步骤

### Plan
- 读取 PRD / 用例清单，识别功能模块集合与指标需求（性能、面积、功耗、时延）
- 明确指标条目及其**测试方法归属**：功能/吞吐/时延 → 仿真；Fmax/面积 → 综合；功耗 → 功耗分析
- 与 A1 建立对应关系，缺失指标项登记回 A1 或 open issue

### Execute
- **功能规格**：按 `.opencode/skills/node-A2-system-spec/assets/templates/spec-system.md` 第 2 节填写功能模块清单、关键功能行为定义
- **性能指标表**：每项指标给出 目标值 + 单位 + 测试方法 + 来源需求，覆盖 Fmax / 吞吐 / 面积 / 功耗 / 时延
- **约束章节**：工艺、时钟（频率/域）、复位、电源（电压域/档位）、兼容性标准（总线协议版本、外设标准）
- **可测试性要求**：DFT 策略（扫描链接入）、调试接口、自测试（BIST）需求
- **验收标准**：功能验收点（对应 D 阶段验证计划 D1 承接）、收敛验收点（对应 F 阶段时序）
- **需求追溯**：每项功能规格/指标标注来源 REQ/SC 编号（A4 将据此建 RTM）

### Measure
- 指标条目数，逐项核对是否含（目标值 / 单位 / 测试方法 / 来源需求）四要素
- 功能规格条目是否都可追溯到 REQ；每个 REQ 是否至少映射一条规格
- 测试方法与工具链对应性核对

### Judge
- 对照收敛判据：指标可量化、可测试、与场景对应
- 不满足（存在无单位/无测试方法/无来源的指标行）→ 回到 Execute 补齐；满足 → 进入质量门评审

## 6. 收敛判据（DoD）

- **指标可量化、可测试，与场景对应**

判定方法：
- 每个性能指标行含 目标值 + 单位 + 测试方法 + 来源需求 四要素（`AIFlow/scripts/check_ppac.py` 无空项输出）
- 测试方法可落地：功能/吞吐/时延 → 仿真（cocotb/UVM）；Fmax/面积 → 综合（DC/GENUS）；功耗 → 功耗分析（Primetime PX）
- 每项指标至少关联一个 A1 场景 `SC`；每项功能规格可追溯到 `REQ`
- 与 A1 需求无未追溯项（无 REQ 指向不存在，无规格无来源）
