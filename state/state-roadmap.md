# 芯片优化方向 Roadmap（统一待办清单）

> 用途：统一登记开发过程中随时产生的、超出当前收敛范围的优化想法 / 增强方向（下一版芯片、架构备选、流程改进、技术预研）。
> 维护者：orchestrator（唯一写入者，与 state-tracker 纪律一致）。
> 登记时机：① 用户随时提出"记一下 / 待办 / 优化方向 / 下一版可以…"；② 每个节点质量门签核时 orchestrator 主动询问；③ 架构节点（B1/B3/B5）启动前先读本清单。
> 条目编号：`RT-<NNN>` 项目全局递增；登记/校验见 `scripts/roadmap_check.py`。
> 与 OI 的区别：OI 是当前版本规格歧义澄清（必须在当前版本关闭）；Roadmap 是当前版本收敛范围之外的增强 / 未来方向（不阻塞当前版本）。

## 条目结构（每条目固定字段）

| 字段 | 说明 |
|------|------|
| 标题 | 一句话命名 |
| 分类 | 下一版增强 / 架构备选 / 流程改进 / 技术预研 |
| 状态 | idea / planned / in_progress / adopted / deferred / rejected |
| 来源 | 提出人 + 日期 + 来源节点/场景 |
| 动机 | 为什么想优化（痛点 / 场景） |
| 方案概述 | 技术方向一句话 |
| 期望收益 | 量化或定性收益 |
| 影响范围 | 涉及的模块 / 文档 / 节点 |
| 关联 | 相关 ADR / OI / M 指标 / 其他 RT |
| 处置建议 | 建议在哪评估、下一步动作 |

## Roadmap 条目

### RT-001 — 内存映射 SPI Flash 访问（MMIO 只读窗口 / XIP）
- 标题：内存映射 SPI Flash 访问（MMIO 只读窗口 / XIP）
- 分类：下一版增强（架构备选）
- 状态：idea（待 B1 评估）
- 来源：用户，2026-08-20，A3 签核后提出
- 动机：当前 Flash 仅 PIO 访问，CPU 需软件驱动 SPI 寄存器逐字节搬数据；希望 CPU 像读内存一样直接访问外部 Flash 内容
- 方案概述：增加内存映射 Flash 控制器，把 SPI Flash 内容映射为 MMIO 只读窗口（AXI 从端口）；CPU load 命中窗口时控制器自动执行 SPI 读命令并返回数据；读走 MMIO、写/擦除仍走寄存器（PIO）；可选 XIP（代码直接在 Flash 执行）与缓存/预取
- 期望收益：免软件搬运；大数据读取（配置表/字库/只读常量）编程简化；XIP 可省启动拷贝
- 影响范围：BLOCK-05 扩展或新增 BLOCK-15；spec-005 新增 MMIO 只读窗口（可挂 0x5000_0000 未映射区）；spec-004 M 表（新增 XIP/读带宽指标）；B1/B3（缓存/预取/线宽）；C1/C2（控制器微架构/契约）；A3 已冻结需走变更流程
- 关联：ADR-009（高速 SPI 待 B1）；RT-002（高速 SPI）；M-006/M-013；OI-A3-006（已关闭）
- 处置建议：B1 架构评审纳入评估，与 RT-002 合并评估；B4 建模量化"无缓存 MMIO vs 带缓存"的带宽/面积/启动时延收益；若采纳进入下一版 PRD（增补 REQ 走 OI 流程）

### RT-002 — 高速 SPI（QSPI / 160MHz 级）
- 标题：高速 SPI（QSPI / 160MHz 级）
- 分类：架构备选（下一版增强）
- 状态：idea（待 B1 评估）
- 来源：用户，2026-08-20，A3 签核讨论中提出
- 动机：当前单线 SPI SCLK ≤ 12.5 MHz（Fsys/4），启动与大数据读带宽受限；QSPI NOR Flash 器件可达 104–166 MHz
- 方案概述：SPI 升级为 QSPI（x4）并提高 SCLK（需独立 SPI 时钟/PLL 或提高 Fsys）；与 RT-001 XIP 配套可构成完整高速 Flash 通路
- 期望收益：读带宽 ×4~×16；启动时延可从 ~60ms 降至 ms 级；支撑 XIP
- 影响范围：BLOCK-05（SPI master）、BLOCK-11（时钟架构：单域 → 独立 SPI 时钟域）、M-006、A3 引脚（新增 IO2/IO3）、B1/B3/B4
- 关联：ADR-009（160MHz 待 B1 评估）；RT-001；M-006/M-013
- 处置建议：B1 时钟架构评审一并评估；若上 160MHz 需同步修订 M-006/BLOCK-05 并触发 A3 变更流程

## 状态流转规则

```
idea →（评估后）→ planned / adopted / deferred / rejected
```

- adopted：折入当前或下一版 PRD（增补 REQ 走 OI 流程），条目标注 adopted 并登记落地节点
- deferred：延后，保留条目
- rejected：标注原因，保留留档（登记即留档，不删除）
- 评估入口：架构类条目在 B1/B3/B5 评审；流程类在 ADR 评审；技术预研类可随时
